# 歌切规范 V4（行业标准对齐版）

> 制定于 2026-11-09。取代 V3 中与此冲突的条目。所有数字都可量化、可自动判定，
> 不达标一律不入库，并写入 `queue/qc_rejects.json` 留痕。

## 零、参考的行业标准

| 领域 | 参考 | 我们采用的换算 |
|---|---|---|
| 字幕/歌词时间轴同步容差 | Netflix Timed Text Style Guide：同步误差 ≤ 4 帧（≈167ms）；相邻两条间隔 2 帧 | 行级中位误差 ≤ **250ms**，95 分位 ≤ **600ms** |
| 单条字幕最短/最长展示 | Netflix TTSG：最短 5/6 秒、最长 7 秒（按语言页略有差异） | 单行展示 **0.8–12 秒**；行间隔 ≥ **0.6 秒** |
| 静音检测阈值与最短静音 | 通行做法：−30~−50 dBFS，最短静音 300–500ms，两侧留白 100–200ms | 阈值 = 噪声底+8dB 且落在 **[−50,−40] dBFS**；最短静音 **500ms**；留白 **起 150ms / 收 250ms** |
| 逐字卡拉OK | 商业卡拉OK与 UltraStar 生态逐字误差目标 ±50ms 级；ASS `\k` 精度为厘秒 | 单字 ≥ **80ms**，行内逐字时长和与行时长误差 ≤ **2cs** |
| 清唱/伴奏分离 | ICASSP 论文常用分离后人声做词级对齐，但用户明确否决分离 | **不分离**，用全场 ASR 词级时间戳替代 |

References:
- Netflix 字幕时间规范：[Timed Text Style Guide: Subtitle Timing Guidelines](https://partnerhelp.netflixstudios.com/hc/en-us/articles/360051554394-Timed-Text-Style-Guide-Subtitle-Timing-Guidelines)
- 静音检测阈值/留白通行参数：[Silence Detection: Definition, Thresholds & Padding](https://valmera.io/glossary/silence-detection)
- 词级歌词-音频对齐研究：[Word-Level Lyrics-Audio Synchronization Using Separated Vocals (ICASSP 2017)](https://dihana.cps.unizar.es/proceedings/ICASSP/2017/pdfs/0000646.pdf)
- 逐词对齐精度工具实践：[Word-Level Timing Editor in Epitrite](https://www.epitrite.com/blog/word-level-timing-editor-guide)

## 一、音频与切片（硬性）

1. 只做**流复制**（`-c copy`），零重编码、零滤镜、零重采样；单区间，禁止拼接。
2. 音源固定 B 站最高档（实测 30280 / 233kbps / 48kHz / 立体声）。
3. **不做人声伴奏分离**（会引入残留与假混响）。
4. 切点必须落在**检测到的静音段内部**：
   - 静音判据：20ms RMS → dBFS；噪声底 = 10 分位；阈值 = clamp(噪声底+8dB, −50, −40)
   - 静音段最短 **500ms**
   - 起点 = 静音段结束 − 150ms；终点 = 静音段开始 + 250ms
5. 找不到合规静音段（前后 20s / 12s 内）→ **该首不发布**，不做“硬凑”。

## 二、区间完整度（防截断、防拖尾）

以官方歌词为准，锚定首末句后判定：

1. 首句匹配时刻距切片开头 ≤ **8 秒**（前奏最多 8 秒）
2. 末句匹配时刻距切片结尾 ≤ **12 秒**（尾奏最多 12 秒）
3. 切片时长 ≥ **90 秒**
4. 末句匹配时刻必须 ≤ 切片时长（唱到结束，且不得超出）

## 三、歌词与时间轴（逐首体检，任一项不过即拦截）

1. **锚定率 ≥ 90%**：官方歌词行在演唱中被定位到的比例
2. **歌词文字召回 ≥ 75%**：发布出去的歌词字符，确实出现在该场演唱转写里
3. **行级误差**：每行起始时间与其首个字在转写中的时间差 → 中位 ≤ 250ms，95 分位 ≤ 600ms
4. **单调性**：时间严格递增，零倒序
5. **行间隔**：任何相邻行 ≥ 0.6 秒；单行展示 0.8–12 秒
6. **额外行**：不属于官方歌词的行 ≤ 5%
7. **首行时间** ≤ 8 秒（与“前奏 ≤8s”一致）

## 四、逐字字幕（03_karaoke.ass）

1. 单字时长 ≥ **80ms**（避免闪烁）
2. 行内 `\k` 时长之和与行时间差的误差 ≤ **2 厘秒**
3. 行与行不重叠；字幕总长与音频时长一致

## 五、发布流程

1. 每首依次过：门槛（gates）→ 质检（qc）→ 生成三件套 → 写索引。
2. 任何一项不过：**不入库**，把原因与指标写进 `queue/qc_rejects.json`。
3. 每场结束重建页面；每日汇总一次拦截清单（歌名＋原因＋指标）。
4. 队列串行，重活经 `heavy.sh`；同等素材重跑必须替换旧条目，不并存。

## 六、质检指标留痕

每首入库时记录：锚定率、文字召回、行数、行级中位误差、95 分位误差、
最小行间隔、切片时长、首句偏移、末句偏移。用于事后抽查与回归对比。

# 第五章 V5 补充：全流程专业校验（2026-11-09 二次加严）

> 本章对"代码/规则/流程"逐环节对标，补齐 V4 遗漏项。所有条目都有代码落点。

## 5.1 源音轨验收（`lib/audiospec.py: check_source`）
| 要求 | 阈值 | 依据 |
|---|---|---|
| 编码 | AAC（mp4a） | 流复制前提：不解码不换编码 |
| 采样率 | 48000 Hz | B 站最高档实测 |
| 声道 | 立体声 2ch | 同上 |
| 码率 | ≥200 kbps | 233 kbps 档位验收下限 |
不达标 → 该场直接失败（`reject` 记录），不进入切歌。

## 5.2 切点帧对齐（`audiospec.frame_align`）
流复制的切点必须对齐 AAC 帧边界（1024 样本 @48k = **21.33ms** 一格），
否则起始帧不完整会出现"咔"声或丢帧。所有 na/nb 在切之前统一量化到帧边界。

## 5.3 成品校验（`audiospec.check_cut`）
1. 编码/采样率/声道与源一致（证明零重编码）
2. 时长与计算值偏差 ≤ **0.15s**
不达标 → 不发布。

## 5.4 响度与真峰值（EBU R128，`audiospec.loudness`）
- 只测量，**不修改音频**（保持"最真实的声音"原则）
- 记录 integrated LUFS 与 true peak 到 `queue/qc_metrics.jsonl`
- 提示区间：整体响度 −24~−6 LUFS、真峰值 ≤ −1 dBTP；越界只告警不阻断

## 5.5 说话占比（用户既有标准，落到代码）
片段内被判定为"说话"的时长占比 ≤ **8%**，超过不发布。依据 `qwen_sent` 逐句标签。

## 5.6 识曲一致性（`lib/identify2.py`）
1. 多路召回：≥3 段纯中文片段分别检索 + 大模型候选
2. 歌词拼音二元组打分 ≥ **0.45**
3. **至少 2 个独立候选条目**指向同一歌名（去括号/版本词后比较）才算确认
4. 优先原唱：Live/翻唱/多艺人条目各扣 0.05~0.08
宁缺勿错：任一条不满足即判"识别不出"，不发布。

## 5.7 逐字字幕可读性（`tools/make_ass.py`）
1. 单屏 ≤ **16 个汉字**，超出按就近空格折成两屏
2. 两屏之间留 **≈70ms（2 帧）**
3. 单字 ≥ **80ms**
4. 末行展示上限 **12 秒**
依据：中日韩字幕通行 14~16 字/行、Netflix 单条 ≤7 秒（歌词允许更长的持续行，故取 12 秒上限）

## 5.8 指标留痕与回归（`queue/qc_metrics.jsonl`）
每首入库写入：版本号、切片起止、锚定率、文字召回、行级中位/95 分位误差、同步率、
过密行、额外行、说话占比、响度/真峰值、静音阈值级别。
用于：事后抽查、跨版本回归比对、按歌定位问题。

## 5.9 流程铁律（不变）
1. 串行、单场、`songcut-v3.service` 托管；`run/PAUSE` 存在即暂停
2. 任一验收项不过 → 拦截并记录，**绝不入库**
3. 重跑替换旧条目不并存；宁缺勿错

## 5.10 运行期健壮性（2026-11-09 实战补充）

1. **分类缓存自检**：`labels.json` 若覆盖不足 95% 句子，或长场次演唱占比 <3%，
   判定为上次中途掉线留下的残缺缓存，作废重做（`pipe_v3.classify_and_region`）。
2. **同济通道自动重连**：`qwen_sent` / `judge_lib` 遇到网络异常即调用
   `llmcfg.ensure_online()`（只发 on，不重启 dsh-web），避免整场因 VPN 抖动失败。
3. **静音切点兜底**：找不到 ≥500ms 合规静音时，回退到"演唱句边界"（ASR 句边界＝词边界），
   并在日志标注"改用句边界"；窗口 <60s 仍不发布。
4. **识曲单路例外**：只有 1 路候选但歌词吻合度 ≥0.60 时接受；否则判"识别不出"。
5. **队列每轮重读磁盘**：`run_v3` 每次取任务都重新读 `streams_v3.json`，
   外部重置/插队即时生效；写回前再读一次，避免覆盖外部改动。

## 5.11 同济 API 限流应对（2026-11-09 实测）

1. **症状**：`/v1/models` 正常 200，但所有模型的 `/v1/chat/completions` 返回 429（限流），
   表现为分类整批失败 → 若代码静默丢弃会造成"整场 0 候选却显示完成"。
2. **强制规则**：
   - 分类必须做**覆盖率校验**（≥95% 句子），不足则重做，仍不足判该场失败重排队；
   - 429 必须**退避重试**（25s 起，逐轮加长），禁止快速失败；
   - 批间隔自适应：遇 429 加倍延迟，连续成功后逐步回落。
3. **省额度手段**（已落地）：
   - 识曲先查本地歌词库（零请求命中熟歌）；
   - 去掉"曲名二次规范化"这一类可省的 LLM 调用；
   - 分类批大小 120，候选歌词抓取上限 3。
4. **限流期间的生产安排**：用 `tools/prewarm_asr.py` 预热后续场次转写（只用本地 whisper，
   不消耗 API），API 恢复后每场约 10 分钟即可出歌；`tools/auto_resume.py` 每 10 分钟探活并自动恢复队列。
