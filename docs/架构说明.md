# 架构与数据流

## 1. 每场（P1/P2 独立）的数据流

```
bvid(+page)
   │  bili.fetch_audio(?p=n, 取最高档 id=30280)
   ▼
res/<tag>.m4a ── decode_wav ──► /tmp/sw/<tag>/full.wav (16k mono)
                                     │
                    asr_chunk (300s/块, 无VAD, 词级时间戳)
                                     ▼
                       queue/asr_v3/<tag>.jsonl  ← 持久化缓存（断点续跑）
                                     │
                    qwen_sent（批量逐句判 演唱/说话，限流退避）
                                     ▼
                    seg_regions（合并候选区间，gap 容差 22s、最短 60s）
                                     ▼
   ┌──────────── 每个候选区间 ────────────┐
   │ identify2：多段检索网易云 → 候选歌词   │
   │   文字召回≥40% + DTW 对齐≥60% → 选定  │
   │ cutwin.audio_window：只看音频+标签定切点│
   │   → 帧对齐 → ffmpeg -c copy 切片       │
   │ audiospec：参数/时长/响度校验          │
   │ align_lib：拼音 DTW + 插值 + 重锚 → LRC│
   │ gates + qc：锚定/覆盖/同步/单调/误差   │
   │ mimo.verify_song：3×20s 音频独立验收   │
   │ make_ass：LRC → 逐字 ASS               │
   └───────────────┬───────────────────────┘
                   ▼
   library/<日期>_<歌名>_<原唱>/{01,02,03}
   queue/songs_index_new.json（+qc_metrics.jsonl / qc_rejects.json）
                   │
              build_site.py → 静态播放页（注入 SONGS JSON）
```

## 2. 关键取舍

| 取舍 | 选择 | 原因 |
|---|---|---|
| 是否重编码 | 否（`-c copy`） | 保原声；切点落在静音里所以不需要淡入淡出 |
| 是否人声分离 | 否 | 分离会引入残留与假混响；用户明确要求"最真实的声音" |
| 切点依据 | 音频+标签，不用歌词 | 避免循环依赖（歌词错→切点错→质检自证） |
| 排轴依据 | 本地 whisper 词级时间 + 拼音 DTW | MiMo 文本更准但句级时间偏 3~5 秒且粒度粗 |
| 歌词来源 | 网易云官方 | 按曲名+原唱反查，禁用翻唱 |
| 云端分工 | 文本判定/音频验收走云端，时间轴走本地 | 成本与精度折中 |

## 3. 为什么会"少而准"

严格门槛下每场只收 1~5 首，被拦的典型原因（见 `logs/qc_rejects_sample.json`）：

- **同步率不足**：ASR 对重复副歌识别混乱 → 行级时间偏 2 秒以上
- **锚定不足**：官方歌词有大段未演唱（现场唱缩短版）
- **歌词召回低**：识曲认错（标题恰好含该句词）→ 被 DTW/音频复核拦下
- **说话占比超 8%**：切片内夹带念弹幕/报谢
- **首行过晚 / 拖尾**：前奏或尾奏超出规范

## 4. 运行保障

- `scripts/heavy.sh`：`flock` 单锁 + 可用内存闸门（<1200MB 拒绝启动，<350MB 主动退出）
- 队列为 systemd 独立服务，与聊天机器人解耦，机器人重启不影响队列
- `run/PAUSE` 文件存在即暂停（优雅停机）
- API 限流（429）：指数退避 + 自动重连校园 VPN；恢复后自动续跑
- 断点续跑：转写缓存按 `bvid(_pN)` 命名；成品按路径去重；每轮重读队列文件
