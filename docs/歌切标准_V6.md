# 歌切标准 V6（分阶段 + 行业对标）

> 2026-11-10 制定。核心变化：**流程分阶段、每阶段独立判定，互不耦合**；
> 每一条都能自动判定，不达标即拦截并记录原因。

## 0. 流程分段（严格串行，一项一项来）

```
S1 下载  → S2 切片 → S3 转写 → S4 认歌+歌词 → S5 排轴+质检 → S6 打包
每阶段有独立的"入口校验 / 出口校验"，上游不合格不进入下游。
切点只看音频与演唱标签；歌词只用于 S4/S5，绝不回改切点。
```

## S1 下载与源校验（`lib/audiospec.py`）

| 项 | 标准 | 依据 |
|---|---|---|
| 编码 | AAC（mp4a） | 流复制前提，不解码不换编码 |
| 采样率 | 44100 或 48000 Hz | B 站平台上限（老录播仅 44.1k） |
| 声道 | 立体声 2ch | 平台最高档 |
| 码率 | ≥128 kbps（优先取最高档，记录真实值） | 平台最低可接受档 |
| 时长一致性 | 转写缓存必须与音轨时长匹配（±5%，且不超 +60s） | 防"拿错音轨却显示成功" |

## S2 切片（`tools/boundary.py` + `lib/cutwin.py: audio_window`）

| 项 | 标准 | 依据 |
|---|---|---|
| 静音判据 | 20ms RMS→dBFS；噪声底 = 10 分位；阈值分级 floor+6/+10/+14/−25 dBFS | 广播通行 −30~−50 dBFS 区间 |
| 最短静音 | **500 ms** | 通行 300–500 ms，取上限 |
| 起点 | 首唱句前 3s；可回溯吃静音，最多 **20s** | 前奏上限 |
| 终点 | 末唱句后 4s；可延伸吃静音，最多 **12s** | 尾音上限 |
| 时长 | **90–600 s** | 太短不完整、太长必混入闲聊 |
| 帧对齐 | 对齐 AAC 帧边界（1024 样本 @48k ≈ 21.33 ms） | 防起始帧破损 |
| 说话占比 | 片段内判定为"说话"的时长 **≤8%** | 用户既有标准 |
| 成品一致性 | 编码/采样率/声道与源一致；时长偏差 ≤0.15s | 证明零重编码 |
| 响度 | EBU R128 测量并记录（−24~−6 LUFS、真峰值 ≤−1 dBTP，越界仅告警） | 只测不改，保真 |

## S3 转写（`lib/asr_chunk.py`）

| 项 | 标准 | 依据 |
|---|---|---|
| 模型 | faster-whisper small int8，`vad_filter=False` | VAD 会把演唱当非语音丢弃 |
| 分块 | 300 s 分块转写，避免整段读入内存 | 防 OOM |
| 完整性 | 覆盖率 ≥95% 且不超过音轨时长 105% | 防半截转写被复用 |

## S4 认歌与歌词（`lib/identify2.py`）

| 项 | 标准 | 依据 |
|---|---|---|
| 多路召回 | 多段纯中文片段检索网易云（≤4 段）+ 大模型候选 | 单一来源易错 |
| 歌词召回 | **≥40%** | 低于此值必为错歌 |
| DTW 对齐率 | **≥60%** | 防"标题里恰好有这句词"的李鬼 |
| 综合评分 | 0.4×字面相似 + 0.35×召回 + 0.25×对齐率，取最优 | 多信号融合 |
| 版本偏好 | 排除伴奏/纯音乐/Karaoke；Live/翻唱/多艺人扣分 | 原唱优先 |
| 缓存 | 按文本哈希缓存，命中即复用 | 省额度、可复现 |

## S5 排轴与质检（`lib/align_lib.py` + `lib/qc.py` + `lib/gates.py`）

| 项 | 标准 | 依据 |
|---|---|---|
| 对齐算法 | 拼音 DTW 强制对齐 + 字符加权插值 + 局部重锚 + 压缩簇修复 | 禁线性缩放/字数平均 |
| 锚定率 | **≥85%** | Netflix 级字幕要求"几乎每行都定位得到" |
| 歌词覆盖（相对官方行数） | **≥80%** | 防现场唱半首 |
| 歌词文字召回 | **≥66%** | 防张冠李戴 |
| 行级同步率 | **≥80%** 的行在 ±2 s 内命中演唱位置 | 见下方说明 |
| 行级误差中位 | **≤0.30 s**；95 分位 ≤0.90 s | Netflix 同步容差 ≈4 帧(167ms) 的宽松换算 |
| 单调性 | 严格递增、零倒序；相邻行 ≥0.6s；过密行 0 容忍 | 字幕可读性 |
| 首行/末行 | 首行 ≤8 s；末行不超时长；末行后空档 >20s 判拖尾 | 防抢跑/拖尾 |
| 额外行 | 非官方歌词行 ≤5% | 防幻觉行混入 |

## S6 打包

三件套：`01_audio.m4a`（流复制原码流）、`02_lyrics.lrc`（逐行时间轴）、`03_karaoke.ass`（逐字高亮）。
字幕：单屏 ≤16 汉字、折行间隔 ≈70 ms、单字 ≥80 ms、行间不重叠、末行 ≤12 s。
指标落盘：`queue/qc_metrics.jsonl`（含版本号、锚定/召回/同步/误差/说话占比/响度）。

## 7. 与业界先进做法的差距（诚实说明）

| 业界做法 | 现状 | 差距与影响 |
|---|---|---|
| WhisperX 用 wav2vec2 **音素级强制对齐**，词级时间戳中位误差约 **21 ms**（Interspeech 2023） | 我们用 faster-whisper 自带词级时间戳 + 拼音 DTW | 我们的同步率指标是"与 ASR 时间戳一致性"，**不是独立真值**；真实误差可能大于 0.3s |
| 歌词-音频对齐研究普遍用**人声分离 + 音高/音素混合**建模 | 按用户要求**不做人声分离** | 无伴奏干扰时更准，我们主动放弃这条路 |
| MIREX 类结构分析做歌曲边界（beat/segment 模型） | 我们用静音 + 演唱标签启发式 | 音乐连续无静音的歌回（连唱串烧）可能切不开 |
| 字幕行业标准（Netflix）同步容差 ≈4 帧、单条 5/6–7 s | 我们放宽到中位 0.3s、单行 ≤75s（歌词特性） | 有意放宽，因为歌词行常跨长音 |

**若要达到 21 ms 级真值精度**：需引入 CTC 强制对齐（`torchaudio.pipelines.MMS_FA`，模型约 1.2 GB，
本机 3.7 GB 内存需串行跑），单场耗时预计增加 1–2 倍。是否启用待用户决定。
