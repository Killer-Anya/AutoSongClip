# V2 历史版本复现 / Reproducing the Historical V2 Pipeline

[简体中文](#简体中文) · [English](#english)

## 简体中文

本页记录 V2 歌切实验的运行方法。线上曲库使用 V1。下列命令运行 V2，无法复现 V1 的切点、排轴或曲库。[项目复盘](项目复盘.md#简体中文)

### 安装和运行

在 Ubuntu 或 Debian 上，用 Bash 在仓库根目录安装依赖及本地 Whisper small 模型。

```bash
sudo apt install python3 python3-venv ffmpeg util-linux procps
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -c "from huggingface_hub import snapshot_download; snapshot_download('Systran/faster-whisper-small', local_dir='models/small')"
```

在同一个终端配置兼容的文本判断接口，将示例地址和模型名换成服务商给出的值。服务器试运行用 GLM-5.3-Flash 做文本判断。下面关闭 MiMo，沿用 V2 的歌词质检，音频复核记录为 `skipped`。替换录播地址、标题和日期后运行。链接中的 `p=2` 选择第 2 P。

```bash
export JUDGE_API='https://your-provider.example/v1/chat/completions'
export JUDGE_HEALTH='https://your-provider.example/v1/models'
export JUDGE_MODEL='your-model-name'
read -rs -p 'API key: ' JUDGE_KEY
export JUDGE_KEY

MIMO_VERIFY=0 MIMO_ASR=0 MIMO_ANCHOR=0 python3 pipeline/pipe_v3.py \
  'https://www.bilibili.com/video/BV1xxxxxxxxx/?p=2' '场次标题' 2026-01-01
```

如需恢复 V2 的可选音频抽查，使用本机 `127.0.0.1:18090` 上支持 MiMo-V2.6-Flash 的代理，配置 `TONGJI_API_KEY`，并把上述命令的 `MIMO_VERIFY` 改为 `1`。可以保留本地转写与排轴配置。[V2 架构与接口](架构说明.md)

### 缓存重处理与发布

- 暂时没有模型 API 时，可运行 `python3 pipeline/pipe_offline.py BV号 2`。示例处理第 2 P。需要源音轨 `res/<场次>.m4a`、转写 `queue/asr_v3/<场次>.jsonl` 和本地歌词语料或已有曲库。找不到歌词时仍可能访问网易云音乐。缓存准备、文件命名和批量入口见[队列说明](../queue/README.md)。
- 单场产物写入 `library/`，待审核条目写入 `queue/songs_index_new.json`。如需发布到自己的预览曲库，抽听后只保留已确认条目，按索引中的相对路径把对应 M4A 放进 `site/audio/`，再运行 `python3 tools/publish_new.py` 构建页面。[播放器说明](../site/README.md)

### V2 服务器实测环境

2026 年 11 月 12 日的交接记录使用 AMD EPYC 7K62 上的 2 vCPU、3,723 MiB 内存和约 2 GiB Swap。系统是 Ubuntu 24.04.4 LTS，使用 Python 3.12.3 及 FFmpeg / FFprobe 静态构建 `n9.0.2-17-g2a571b6068`。磁盘约 69 GB，当时剩余约 36 GB。

任务串行运行，最近 15 场从下载到打包的中位用时约 31 分钟。交接记录中，命中转写缓存约 10 分钟，冷启动约 35–50 分钟。本地转写使用 CPU，默认内存守卫在可用内存低于 1,200 MB 时延后开始，运行中低于 350 MB 时停止转写。这些是 V2 实测条件和样本耗时。[V2 质量要求](质量要求.md#简体中文) · [批次抽查和指标](指标与质量报告.md)

## English

These instructions run the historical V2 clipping experiment. The live catalog uses V1. Running these commands cannot reproduce V1's clip boundaries, lyric timing, or catalog. [Project retrospective](项目复盘.md#english)

### Install and run

On Ubuntu or Debian, use Bash from the repository root to install the dependencies and the local Whisper small model.

```bash
sudo apt install python3 python3-venv ffmpeg util-linux procps
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -c "from huggingface_hub import snapshot_download; snapshot_download('Systran/faster-whisper-small', local_dir='models/small')"
```

In the same terminal, configure a compatible text review service. Substitute your provider's endpoints and model. The server trial used GLM-5.3-Flash for text review. The command below disables MiMo, keeps V2 lyric checks, and records audio review as `skipped`. Substitute your recording URL, title, and date. The URL parameter `p=2` selects part 2.

```bash
export JUDGE_API='https://your-provider.example/v1/chat/completions'
export JUDGE_HEALTH='https://your-provider.example/v1/models'
export JUDGE_MODEL='your-model-name'
read -rs -p 'API key: ' JUDGE_KEY
export JUDGE_KEY

MIMO_VERIFY=0 MIMO_ASR=0 MIMO_ANCHOR=0 python3 pipeline/pipe_v3.py \
  'https://www.bilibili.com/video/BV1xxxxxxxxx/?p=2' 'Recording title' 2026-01-01
```

To enable V2's optional audio spot checks, use a proxy at `127.0.0.1:18090` that supports MiMo-V2.6-Flash, set `TONGJI_API_KEY`, and change `MIMO_VERIFY` to `1`. Transcription and alignment can still run locally. [V2 architecture and service configuration](架构说明.md)

### Process cached inputs and publish

- Without model API access, run `python3 pipeline/pipe_offline.py BV_ID 2` for part 2. This requires source audio at `res/<recording-tag>.m4a`, a transcript at `queue/asr_v3/<recording-tag>.jsonl`, and a local lyric corpus or existing catalog. It may query NetEase Cloud Music for missing lyrics. See the [queue notes](../queue/README.md) for cache preparation, file names, and batch processing.
- The run writes files to `library/` and review candidates to `queue/songs_index_new.json`. To publish to your own preview catalog, listen to the results and retain only approved entries. Place each matching M4A under `site/audio/` at the relative path listed in the index, then run `python3 tools/publish_new.py`. [Player notes](../site/README.md)

### V2 server baseline

The November 12, 2026 handoff records 2 vCPUs on an AMD EPYC 7K62, 3,723 MiB RAM, and about 2 GiB swap. The server ran Ubuntu 24.04.4 LTS with Python 3.12.3 and the FFmpeg / FFprobe static build `n9.0.2-17-g2a571b6068`. The volume held about 69 GB with about 36 GB free at the time.

Jobs ran one at a time. The most recent 15 sessions took a median of about 31 minutes from download to packaging. The handoff records roughly 10 minutes with a transcript cache and 35–50 minutes for a cold run. Local transcription ran on the CPU. By default, the memory guard delays startup below 1,200 MB available and stops transcription below 350 MB available during a run. These figures describe the recorded V2 environment and runs.
