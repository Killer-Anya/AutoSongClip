## 简体中文

### 2026-11-09 前 · V1 上线

- 线上 V1 曲库整理了 235 首演唱版本。按 Anya 的运行交接，V1 用本地 Whisper、GLM 文本判断、网易云歌词与人工抽听验收。V1 没有使用 MiMo 音频复核。

### 2026-11-09 至 2026-11-10 · 分类服务异常与缓存重处理

- 历史运行记录显示，文本分类服务曾连续返回 HTTP 502。探活脚本约每 10 分钟检查一次，记录在 11 月 10 日 01:58 服务恢复后解除暂停。[恢复记录](../logs/rate_limit_recovery_sample.log)
- 缓存重处理复用已有音轨和转写结果，先从本地歌词语料识别候选，候选不足时用音频片段和歌词检索补查。样本记录了有成品、无新增和无候选三种结果。重处理可能查询外部歌词服务。[缓存重处理样本](../logs/offline_mode_sample.log) · [处理入口](../pipeline/pipe_offline.py)

### 2026-11-10 · V2 分段验收

- 把场次分类、识曲、切点计算、歌词对齐和成品校验拆成阶段。源音轨和切片参数单独记录，识曲不确定、歌词覆盖不足、说话占比超限、首行过晚等结果各自留痕，便于定位失败阶段。[架构说明](架构说明.md) · [拦截记录](../logs/qc_rejects_sample.json)
- 一场 6,908 秒的样本录播记录了 1,244 句转写、16 个候选区间和 3 条新增入库记录。同一日志还记录了因覆盖不足和说话占比超限被拒的候选。入库数量来自该次运行。[单场处理日志](../logs/stream_pipeline_sample.log)
- 样本里有若干行在「音频复核通过」后仍打印 `命中None 置信None`。这些行只说明当时的程序状态，无法证实音频模型返回了完整的肯定结论。对齐的自动指标也以 ASR 时间戳为参照，仍需用人工标注或其他独立参照验证实际误差。[样本日志](../logs/stream_pipeline_sample.log) · [指标与质量报告](指标与质量报告.md)

### 2026-11-10 · MiMo 转写实验

- 云端音频模型的样本记录中，120 秒音频耗时 8.3 秒，300 秒音频耗时 21.6 秒。这个结果记录的是特定样本的请求耗时，完整场次还包括下载、解码、重试、对齐和质检等步骤。[实验数据](../logs/mimo_bench.json)
- 复测记录中，120 秒块的初版提示词输出约 11–13 句，60 秒分块并要求按换气分句后，同等时长输出约 18–19 句。与本地 Whisper 句级时间比较，时间差中位数约为 3–5 秒。本地 Whisper 的词级时间仍用于默认排轴，云端整场转写保留为实验选项。[实验入口](../lib/mimo_asr.py) · [默认转写分支](../pipeline/pipe_v3.py)
- 解析器补齐了三种模型输出形式，包括单时间点、时间区间接下一行正文，以及同一行的区间和正文。实验计时与时间轴对照来自不同记录，复测样本用于判断这个方案能否进入默认路径。[解析实现](../lib/mimo_asr.py)

## English

### Before November 9, 2026 · V1 deployment

- The deployed V1 library contained 235 performances. Anya's handoff records local Whisper, GLM text review, NetEase lyrics, and manual listening for V1. V1 ran without MiMo audio review.

### November 9–10, 2026 · Service interruption and cached reprocessing

- Historical logs record repeated HTTP 502 responses from the text classification service. A health check polled about every ten minutes and cleared the pause after the service recovered at 01:58 on November 10. [Recovery log](../logs/rate_limit_recovery_sample.log)
- The cached workflow reused source audio and transcription results. It looked up candidates in the local lyric corpus first, with an audio and lyric lookup fallback when the corpus returned too few candidates. The sample records accepted items, runs with no new items, and runs with no candidates. The fallback can contact an external lyric service. [Cached run log](../logs/offline_mode_sample.log) · [Entry point](../pipeline/pipe_offline.py)

### November 10, 2026 · V2 stage checks

- Classification, song identification, cut boundaries, lyric alignment, and output validation were recorded as separate stages. Rejection records distinguish uncertain song matches, insufficient lyric coverage, excessive speech, and late first lines. [Architecture](架构说明.md) · [Rejection sample](../logs/qc_rejects_sample.json)
- A 6,908-second recording produced 1,244 transcription segments, 16 candidates, and three new catalog entries in the recorded run. The same run rejected candidates for insufficient coverage and excessive speech. [Single-recording log](../logs/stream_pipeline_sample.log)
- Several audio review lines show `None` for match and confidence while reporting a pass. Those records do not establish an affirmative model result. Alignment measurements use ASR timestamps as a reference. Actual alignment error requires human annotation or another independent reference. [Sample log](../logs/stream_pipeline_sample.log) · [Metrics report](指标与质量报告.md)

### November 10, 2026 · MiMo transcription experiment

- The cloud audio model processed a 120-second sample in 8.3 seconds and a 300-second sample in 21.6 seconds. The timings cover the recorded requests. A complete recording run also includes download, decoding, retries, alignment, and validation. [Benchmark data](../logs/mimo_bench.json)
- Retest notes record about 11–13 lines per 120-second window with the initial prompt and about 18–19 lines per equivalent window using 60-second chunks and a breath-based prompt. The median sentence timestamp difference versus local Whisper was about 3–5 seconds. The default alignment still uses local Whisper word timestamps. Whole-recording cloud transcription remains experimental. [Experimental entry point](../lib/mimo_asr.py) · [Default pipeline](../pipeline/pipe_v3.py)
- The parser was expanded to accept a single timestamp, a range followed by text on the next line, and a range with text on the same line. Request timings and alignment comparisons came from separate records. [Parser implementation](../lib/mimo_asr.py)

### November 11, 2026 · Initial public source release

- Published Chinese and English READMEs, technical documentation, run log samples, and three screenshots of the live player at the time. The repository includes the V2 clipping source and a local player preview entry point. [Initial commit](https://github.com/Killer-Anya/songcut/commit/4e98bf3)
- Release checks covered local preview startup, HTTP byte ranges, and building a sample catalog. Separate run logs document actual recording processing. [Preview documentation](../site/README.md) · [Queue log](../logs/run_v3_sample.log)

### November 12, 2026 · Public package and documentation update

- Added macOS and Windows player launchers. The single-recording entry point accepts a Bilibili URL and part number, rejects nonexistent parts, and can start with an empty catalog. [Quick start](../README.md#quick-start)
- Added an explicit audio-review switch. Missing or incomplete results are recorded as `unavailable`. An explicit opt-out is recorded as `skipped`. Both statuses allow manual listening before publication. [Online workflow](../pipeline/pipe_v3.py) · [Quality requirements](质量要求.md#english)
- Anya reported serial V2 testing on an Ubuntu server with 2 vCPUs and 3,723 MiB RAM. The median for the most recent 15 sessions was about 31 minutes. [Test environment](V2-复现说明.md#english)
- Consolidated the historical V5/V6 quality drafts into the current quality requirements. The originals remain in the [initial source release](https://github.com/Killer-Anya/songcut/tree/4e98bf3/docs).

### November 13, 2026 · Web player redesign

- The 16:9 desktop layout pairs a record that spins during playback with centered lyrics that enlarge the current line. Portrait phones use a single column. Both layouts open the library from the playback controls.
- The Chinese and English toggle updates the interface while retaining the current track, playback position, and library filters. The case study includes new desktop, phone, and library screenshots captured with the sample library. [Screenshot details](images/README.md)

### November 13, 2026 · Catalog rollback and project closeout

- Rolled back the V2 catalog trial and restored the 235-track V1 catalog. Stopped batch clipping and publishing. [Project retrospective](项目复盘.md#english)
